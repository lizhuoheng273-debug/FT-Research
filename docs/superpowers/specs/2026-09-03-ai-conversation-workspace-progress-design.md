# AI 对话工作区与工具进度设计

## 背景

当前 AI 对话已经可以通过后端任务和 NDJSON 事件流输出，但数据工具调用仍可能出现较长的空白等待。最近一次实测中，`query_market_chart` 在模型继续输出前等待了约 110 秒；根因是部分 AKShare 行情调用没有明确的网络截止时间，而且同一轮多个工具按顺序执行。与此同时，工具事件没有进入前端会话状态，用户只能看到笼统的“正在思考”，无法判断是在调用数据还是模型分析。

当前 AI 对话记录位于独立的 `/ai/conversations` 页面。目标是把它并入 AI 对话工作区，使用户可以在同一页面切换不同会话，同时保留旧地址兼容。

## 目标

1. 缩短工具调用的正常等待时间，并在单工具异常时让模型继续回答。
2. 在对话输出区域显示模型阶段和工具阶段的灰色进度提示。
3. 移除 AI 工作区右侧栏，避免上下文和工具记录占据对话空间。
4. 将对话记录放进 `/finance/ai` 工作区左侧，支持搜索、新建和切换。
5. 首次提问后按“入口名称 · 问题摘要”自动命名，保留用户手动改名结果。

## 非目标

- 不修改 GLM API 协议、密钥存储方式或模型输出内容。
- 不删除已有会话、消息、上下文数据或导出能力。
- 不把模型隐藏思维链展示给用户；“模型分析中……”仅表示阶段状态。
- 不移除旧 `/ai/conversations` 深链接，旧地址只负责兼容跳转。

## 方案

### 1. 工具执行与事件流

后端把一次模型循环拆成明确的状态事件：

```text
model_start → tool_start × N → tool_end × N → model_start → delta × N → done
```

事件仍复用现有 `/api/runs/{run_id}/events` NDJSON 通道，新增的进度事件只进入客户端运行状态，不写入最终对话消息。事件字段约定为：

```json
{
  "type": "progress",
  "payload": {
    "phase": "model | tool",
    "status": "running | completed | timeout | unavailable",
    "tool": "query_market_chart",
    "message": "正在调用板块行情",
    "elapsedMs": 1200
  }
}
```

前端将 `model_start` 显示为“模型分析中……”，将 `tool_start` 显示为“正在调用：板块行情……”，并用本地计时器显示已经等待的秒数；工具结束后更新为已完成、超时或不可用。模型出现连续工具轮次时，状态行始终显示当前阶段，不打断已有 delta 内容。

### 2. 工具速度根因处理

正常路径按以下顺序减少等待：

- 同一轮互相独立的工具调用并行执行，最多 4 个并发，模型消息仍按原调用顺序回填。
- 行情工具根据 `period/count` 计算最小必要时间窗口，不再固定请求 1095 天历史数据。
- 板块名称目录和成功的板块行情摘要使用进程内 TTL 缓存，并允许在上游失败时返回最近一次标记为 stale 的结果。
- 对 AKShare/上游请求增加明确的工具级 20 秒截止时间；超时转换为结构化数据缺口，继续下一轮模型分析。超时只作为保护，不替代缩小查询、缓存和并行执行。

工具异常结果使用统一结构：

```json
{
  "status": "unavailable",
  "data_gap": "板块历史行情超过 20 秒未返回，已跳过"
}
```

这样模型能够如实说明数据缺口，而不会让整个运行任务无限保持 running。被截止的底层调用不再阻塞 AI worker；运行管理器仍保留最终任务截止时间和取消能力。

### 3. AI 工作区布局

AI 工作区改为两列：

```text
┌────────────────┬─────────────────────────────────────────┐
│ 对话记录       │ 当前 AI 对话                             │
│ 搜索           │ 标题 / 模型状态                         │
│ + 新对话       │ 用户问题                                 │
│ ● 金融资讯…   │ AI 增量回答                               │
│   每日复盘…   │ 灰色阶段状态：正在调用… / 模型分析中…     │
│   个股研究…   │ 输入框                                   │
└────────────────┴─────────────────────────────────────────┘
```

左侧列表调用已有会话列表 API，当前会话由 URL 的 `conversationId` 标识；切换会话时同时带上结构化入口信息，保证上下文、标题和返回路径正确。桌面端显示固定左栏，窄屏改为顶部可展开的会话选择器。右侧栏及其“已带入上下文”“工具调用记录”卡片全部移除，工具状态统一出现在对话输出区域。

导航中删除 AI 板块的独立“AI 对话记录”项；`/ai/conversations` 保留为兼容路由并重定向至 `/finance/ai`。

### 4. 自动命名

新建会话保存结构化 `source`，例如：

```json
{"type":"news","code":"","panel":"","eventId":"","date":"2026-09-03"}
```

首次提交问题时，服务端仅在当前标题仍为“新对话”时生成标题：

```text
入口名称 · 清理空白后的问题摘要
```

问题摘要截取到标题安全长度，保留中文和关键标点；空问题不会创建或命名会话。手动改名后的标题永远不被后续提问覆盖。旧会话的非结构化 source 使用通用“AI 对话 · 问题摘要”回退规则。

### 5. 错误与兼容

- 工具超时或上游返回 5xx：显示阶段错误状态，向模型提供数据缺口，任务继续。
- 模型 API 超时或事件流断开：沿用现有失败/重连/停止逻辑，最终显示可操作错误，而不是永久 loading。
- 左侧列表加载失败：当前对话仍可使用，列表区域显示错误和重试入口。
- 旧对话、旧 source 和旧 `/ai/conversations` 地址继续可读。
- 右侧栏移除不影响上下文快照，它仍通过原有请求提交给后端。

## 受影响的模块

- `backend/chat.py`：模型阶段、工具并行执行、工具结果和进度事件。
- `backend/research_chart.py`、`backend/market_chart.py`：最小查询窗口、缓存和上游调用边界。
- `backend/tools.py`：工具执行统一超时和结构化数据缺口。
- `backend/ai_jobs.py`、`backend/conversation_routes.py`：持久化进度事件、任务截止和会话自动命名。
- `backend/session_store.py`：结构化 source、默认标题保护和命名更新。
- `frontend/src/lib/conversationClient.ts`：progress/tool 状态归并和新快照通知。
- `frontend/src/hooks/useAiChatSession.ts`：会话状态、工具阶段计时和自动命名调用。
- `frontend/src/pages/FinanceAiWorkspace.tsx`：两列工作区、左侧对话列表和移除右栏。
- `frontend/src/components/ai/AiConversation.tsx`：输出区阶段状态行。
- `frontend/src/components/layout/Layout.tsx`、`frontend/src/router.tsx`：导航调整和旧路由兼容。

## 验证策略

- 后端：工具并行顺序、超时后继续下一轮、progress/tool 事件、按入口和问题命名、手动标题不覆盖、旧 source 回退。
- 前端：progress 状态逐事件刷新、计时器停止、会话列表切换、新建会话、旧地址跳转、两列布局和右栏不存在。
- 集成：使用假的慢工具验证 20 秒内返回结构化缺口；使用假的多工具轮验证并行完成；验证一条真实会话从 tool_start 到 delta/done 的完整事件链。
- 发布前运行前端全量测试、后端非 live 测试、TypeScript 检查和生产构建。
