# A 股权威资讯与热点榜改造设计

**日期：** 2026-08-31  
**状态：** 已批准实施  
**范围：** `backend` 金融资讯服务、来源注册、盘面反查、缓存/API，以及金融资讯前端页面

## 目标

把金融资讯从“每次刷新的一批新闻快照”改造成至少 24 小时滚动的事件库：采集更多可验证的国内外来源，但最终按对 A 股的实际影响筛选、排序和解释。海外重大事件只有在存在可验证的 A 股传导证据时进入 A 股主榜；否则进入最多 5 条的全球观察。

## 约束与非目标

- 不购买数据、不新增真实密钥、不虚构不存在的 API；新增来源只登记真实公开页面/RSS/现有适配器，并记录验证状态。
- 后端统一抓取，上游刷新按 3/10/30 分钟节奏运行，前端只读后端缓存；交易时段外不重复抓盘面。
- SQLite 使用 Python 标准库，数据库和 JSON 缓存都在 `.cache`，不进入 Git；现有 JSON 快照继续可读可降级。
- 代码负责客观分数、实体/行情证据和入榜资格；GLM 只做模糊聚类辅助、导读和候选传导建议，故障时榜单仍可生成。
- 页面展示证据与来源，不做买卖建议、涨跌预测或未经验证的 AI 结论。

## 架构

### 来源层

新增 `backend/financial_news_sources.json` 作为分级来源注册表，来源字段包含 `id/name/tier/type/url/owner/timeField/attribution/compliance/verified`。S 级覆盖证监会、沪深交易所、巨潮/互动易、央行/部委/行业监管、上市公司公告/IR，以及 SEC、主要央行/交易所/核心公司 IR；A级为权威财经媒体；B级为聚合渠道；C级为产业媒体。`source_registry.py` 只接受结构完整、HTTPS/公开协议、时间字段和归属说明齐全的登记项；运行时状态额外报告抓取是否成功、条数、时间字段缺失和合规过滤数。它不把登记项伪装成可调用 API。

现有 AkShare 快讯、`newsradar` RSS、东方财富公告、巨潮公告/互动易能力继续复用；来源名称通过注册表映射分数，不再散落在业务代码的硬编码字典中。新闻原文链接必须原样保留，同时保存归一化链接用于去重。

### 事件库

`financial_news_store.py` 使用 SQLite 表 `reports`、`events`、`event_reports`、`ai_cache`、`market_observations`：

- `reports` 保存单篇报道，唯一键为内容/来源/原文链接指纹，记录首次发现、最近更新和发布时间。
- `events` 保存稳定事件 ID、标题、事件状态、评分 JSON、传导 JSON、更新时间和当前主榜资格。
- `event_reports` 维护事件到报道的关系，转载是同一事件的另一篇报道，不增加独立事件来源数。
- `ai_cache` 按输入内容哈希缓存 GLM 结果，默认每天最多 30 个新候选。
- `market_observations` 保存批量行情/板块观察的时间、来源和证据摘要，便于解释和限流。

每次采集先 upsert 报道，再用最近 72 小时（超过 24 小时最低要求）报道重新聚类并刷新事件；因此后续快讯批次不会覆盖当天早期记录。读取 JSON 时若数据库不可用，回退到现有 `snapshot.json`；写入仍同时生成兼容 JSON。

### 盘面反查与传导

`market_impact.py` 定义可注入的 `MarketEvidenceProvider`。默认实现复用已有批量行业比较/市场概览、腾讯批量行情、东方财富个股新闻/公告、巨潮互动易和板块归属；单次刷新按全站共享缓存、最小间隔和交易时段策略调度，不按用户请求重复抓取。新事件立即查一次，随后在 15/45/90 分钟窗口补查；测试使用注入 provider，不需要线上伪造数据。

传导链固定输出：`催化事件 → 行业 → A 股板块 → 相关股票 → 市场证据`。股票必须来自报道代码、注册实体别名、板块领涨/领跌观察或个股端点返回，且至少有实体或行情证据才能标为“已验证”；仅由 GLM 猜测的股票进入候选字段，不进入主榜。

### 评分与分流

新增 `aShareImpactScore`（本站计算，0–100）及 `impactBreakdown`，权重严格为：

| 维度 | 权重 | 计算原则 |
| --- | ---: | --- |
| 实际市场反应 | 30 | 相关股票/板块的可观测涨跌、成交/涨停扩散，缺证据不加分 |
| 板块扩散 | 25 | 多板块或同板块多股票的批量行情证据 |
| 因果关系 | 20 | 原文实体 + 公告/互动易/个股新闻反查形成可追溯关系 |
| 权威来源 | 15 | S/A/B/C 来源级别与官方确认状态 |
| 时效/持续发酵 | 10 | 发布时间、最近更新、15/45/90 分钟持续更新 |

总分达到 60 才有 `mainBoardEligible=true`；45–59 为 `candidate=true`；低于 45 不入 A 股主榜。官方重大政策/上市公司公告可进入紧要快讯，但仍显示 A 股影响分和证据状态。海外事件若分数低于 45 或置信度为低，只进入 `globalObservation`，最多 5 条。单一传闻、无市场/实体证据的内容不能进入主榜；转载只保留一条事件并在报道时间线展示。

### API 与前端

保持 `/api/finance/news/overview`、`feed`、`events/{eventId}`、`status` 路径与旧字段兼容，新增事件影响、市场证据、传导路径、来源时间线、主榜资格和全球观察字段。`overview` 增加 `aShareHot`、`globalObservation`、`watch`（保留前端自行读取自选股的兼容方式），`status` 增加数据库、来源注册表和盘面反查状态。

前端顺序为：紧要快讯、A 股热门事件榜、我的关注、全球观察、全部资讯流。主榜卡片显示入榜理由、影响分、置信度、板块/股票与更新时间；详情页显示五段传导链、评分拆解、市场证据、独立来源及时间线；所有 AI 字段都标明辅助性质。

## 错误处理与降级

- 单个来源失败只更新该来源状态，保留上次成功数据和 `lastSuccessAt`。
- SQLite 写入失败时从内存批次生成旧格式 JSON；读取失败时返回旧 JSON 或空骨架，不阻塞 FastAPI 启动。
- 行情/公告/互动易反查失败不猜测，影响分维度记为 `unavailable`，并降低置信度。
- GLM 超时、无密钥、返回非法 JSON 或输出未出现于事实中的数字时丢弃该候选；代码评分和榜单照常返回。

## 验收场景

使用注入的确定性 provider 和真实结构的测试输入验证：芒果超媒 `300413` 的 AI 长剧案例由盘面异动反查进入主榜；英伟达财报只有在有 A 股联动证据时进入主榜，否则进入全球观察；韩国熔断同理；单一传闻不入榜；多家转载不重复计数；后续刷新不会丢掉当天早期快讯；GLM 故障不影响榜单。
