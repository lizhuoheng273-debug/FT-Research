# FT-Research 主人 / 游客与 AI 对话设计

日期：2026-09-02。状态：轻量方向已确认，以下细则作为执行默认值；本文件不表示功能已经实现。

## 1. 产品目标

一个项目同时满足个人使用、求职演示和开源自部署，不建立注册、邮件验证、组织、付费订阅系统。

- 入口提供“主人登录”和“游客体验”。主人输入自己的密码，游客无需注册。
- 主人能查看、继续、重命名、删除、导出自己的历史对话；关闭网页再打开仍可恢复。
- 游客之间、游客与主人之间完全隔离。不存在所有访客共用的“guest”账户。
- 在站内切页、关闭对话抽屉后，正在生成的内容继续产生；再次打开能看到已生成内容。
- 统一 AI 对话历史入口，保留各页面不同的股票、行情日期、资讯或分类上下文。

## 2. 体验与生命周期

| 行为 | 主人 | 游客 |
| --- | --- | --- |
| 站内切页、关闭抽屉 | 生成继续，历史保留 | 生成继续，本次体验内可回看 |
| 显式停止 | 取消后续生成，保留带状态的半截回答 | 相同 |
| 刷新 / 新标签页 / 重新访问 | 有效登录可恢复；否则重新登录查看历史 | 重新进入入口，点击游客后创建新会话 |
| 主动退出 | 撤销登录，清除浏览器中的私人视图；主人后台任务可继续 | 立即撤销身份、取消任务、逻辑删除临时对话与临时偏好 |
| 直接关闭标签页 | 后台任务在时限内继续 | 无心跳 90 秒后取消任务，距最后心跳 30 分钟后清理临时数据 |
| 服务重启 | 旧任务标为 interrupted，不自动重试收费请求，已有文字可读 | 未过期临时数据按过期规则清理，不自动续跑 |

游客刷新即重新开始是本计划的明确默认值，不承诺刷新后保留游客记录。页面显示“临时体验：站内切换可保留；刷新或退出后无法找回”。浏览器关闭事件不可靠，因此不得宣传关页瞬间物理删除服务器记录。

游客心跳每 15 秒发一次，后台标签页允许限流造成宽限；任务断联宽限 90 秒、会话闲置期限 30 分钟、绝对期限 2 小时、清理扫描间隔 60 秒。断联取消任务后，回来仍可查看未过期临时会话，但不会自动重新调用模型。SQLite 删除指业务不可访问与定期清理，不是磁盘安全擦除；备份不包含游客记录。

## 3. 简单架构

React 前端 + FastAPI 单进程后端 + SQLite + 后端受限工作线程。沿用 GLM 配置和现有数据工具，不增加 Redis、PostgreSQL、第三方登录或额外模型。

请求链路：登录/游客身份 → 创建对话 → 提交一轮问题获得 runId → 订阅增量事件 → 后端独立执行 → 保存事件与结果。订阅断开与取消任务是两个不同操作。

- SQLite 位于持久化的 `VR_DATA_DIR`，不位于静态资源目录；开启外键、WAL、busy_timeout 和版本化迁移。
- 主人只有一个固定 principal，密码只保存加盐密码哈希。部署者在服务器配置密码哈希，不存在公开默认密码。
- 主人使用服务器随机会话令牌的 HttpOnly Cookie；生产开启 Secure、SameSite=Lax，并对写请求验证 Origin / CSRF。
- 游客使用服务器生成的独立随机令牌，仅保存在当前页面内存，作为 Bearer 发送；不写 localStorage、sessionStorage 或 URL。服务端只保存令牌摘要。
- 每次显式“游客体验”都是新身份；同一浏览器切换主人/游客时先注销当前身份并清理内存。其他标签页收到身份切换广播后清除私人视图并返回入口。
- 公开部署优先同源 `/` 与 `/api`；现有本机 Vite 代理仍可保留。Cloudflare Pages 跨站 Cookie 部署不是本轮默认方案。
- 单后端 worker，无多实例高可用承诺。进程重启不恢复执行，只恢复已存内容和 interrupted 状态。

## 4. 对话与运行模型

- `principal`：id、kind(owner/guest)、创建时间、过期时间。
- `auth_session`：令牌哈希、principalId、有效期、最后心跳、是否撤销。
- `conversation`：id、principalId、kind(chat/debate)、title、source、标识参数、创建/更新时间。
- `message`：id、conversationId、runId、role、content、status、工具来源、创建时间。
- `run`：id、principalId、conversationId、clientRequestId、status、输入上下文快照、序号、错误码、截止时间。
- `run_event`：runId、seq、type、payload、时间；唯一键 `(runId, seq)`。
- `usage_counter`：日期、限额维度、已预留调用次数，防止并发绕过额度。

run 状态：queued → running → completed / stopped / failed / interrupted。终态不可回到 running。回答只有收到真实完整结束事件才标为 completed；仅连接 EOF 不算完成。

clientRequestId 对同一身份唯一：重试返回原 run，不重复收费。对话同一时间最多一个活动任务。增量按有序 seq 保存，可用 `after` 重放与重连；客户端按 seq 去重。可将短时间内的 delta 合并为不超过 100ms 的写入批次，不等待完整回答才显示。

上下文属于每轮问题的不可变快照，包含来源、股票、日期、采集时间；标题更名不改变上下文。后续问题可刷新行情但必须明确新时间。partial/stopped/failed/interrupted 内容可阅读，不作为完整助手回答加入下一轮模型历史，相关未完成 user turn 也排除。

清空、新建、删除分开：新建不会抹掉旧历史；删除自己的活动对话先取消，再做带墓碑的删除，晚到事件不能复活数据。保存完整回答沿用笔记功能，另可导出完整对话 Markdown。

## 5. 页面范围

- 主布局新增“AI 对话”历史入口，不改变现有业务导航顺序。
- 历史页：标题搜索、来源、更新时间、状态、新对话、打开、改名、删除、Markdown 导出；点击能回到合适的研究/辩论视图。
- 现有 `AskAiButton`、金融工作台、股票与分类上下文共用会话客户端；抽屉和工作台只负责展示。
- 多空辩论纳入同一历史/运行管理，保留牛方、熊方、裁判的独立阶段视图，不改成普通文本聊天。
- 登录完成前不渲染私人页面或读取旧 localStorage。主人退出后清除内存查询缓存。
- 旧 `vr-askai-chat:*` 只在主人主动确认后一次性导入；按旧 key 隔离、导入幂等、不导入半截回答。游客不触发旧历史迁移。
- 主人的浏览器自选股、笔记、收藏与自定义 RSS 采用 owner 命名空间，本轮不承诺这些浏览器偏好跨设备同步；游客仅使用内存，退出即丢弃。历史对话本身始终服务端持久化。
- 隐藏持仓、私有研报、反思/CLI 页面和相关 API 限主人，游客不给示例主人数据。公共市场缓存可以共享，私人持仓/聊天/上下文不得进入共享缓存。

## 6. 权限、安全与体验额度

API 按 public / authenticated / owner 分类，未分类默认拒绝。对话详情、消息、增量事件、停止、导出、删除都在服务端按 principal 过滤；前端传入 ownerId 不能授权。其他用户资源统一返回 404，避免暴露存在性。

public 仅健康检查和登录/游客入口；市场读取需要有效主人或游客身份。写入型抓取、配置、上传、报告文件、持仓、CLI 和管理能力限主人；所有模型调用必须经过鉴权和额度检查。公开模式不得保留 `VR_API_KEY` 作为绕过主人认证的入口。工具执行建立允许清单，目前只给游客公开市场查询工具，后续新增工具不能自动获得游客权限。

默认可配置限额：

- 游客每次体验 5 次提问；多空辩论 1 轮，最多启动 1 次，按 3 次提问计。
- 每个身份最多 1 个活动任务；全站最多 2 个运行任务，等待队列最多 8 个，单任务最多 8 分钟。
- 每次模型调用最多输出 4096 tokens；每轮输入问题最多 4000 字符、上下文最多 24000 字符、最多引用 20 条完整历史消息；工具结果也必须裁剪。
- 游客一次聊天最多 4 次模型调用；每 IP 每天最多 30 次、全站游客每天最多 100 次模型调用；进入工具循环的每次模型请求都要原子预留预算，失败但已发出的请求不返还预留。
- IP 只信任服务端连接地址或已配置的可信代理，不信任任意 X-Forwarded-For。限额提示解释共享网络可能共用额度。
- 这些是调用次数/长度限制，不声称等价于精确人民币封顶；主人能在环境配置关闭游客 AI，公共页面仍可浏览。后台收费定时任务默认关闭，主人显式启用。
- 密钥、密码、会话令牌、完整提示词和回答不进普通访问日志。绝不在浏览器展示服务端 Key。

## 7. API 合同

统一身份：`{id, kind: 'owner' | 'guest', expiresAt}`，不返回口令或 Key。

| 方法与路径 | 作用 |
| --- | --- |
| POST /api/auth/login | 主人密码登录，设置 Cookie |
| POST /api/auth/guest | 创建新游客，返回只在内存保存的 token 与身份 |
| GET /api/auth/me | 当前身份，无身份返回 401 |
| POST /api/auth/heartbeat | 更新游客活动时间，不延长绝对期限 |
| POST /api/auth/logout | 撤销登录；游客额外取消并清理 |
| GET/POST /api/conversations | 本人分页历史 / 创建对话 |
| GET/PATCH/DELETE /api/conversations/{id} | 本人详情、改名、删除 |
| POST /api/conversations/import | 主人幂等导入旧浏览器历史 |
| GET /api/conversations/{id}/export | 本人 Markdown 导出 |
| POST /api/conversations/{id}/turns | 创建幂等任务，202 返回 runId 与 status |
| GET /api/runs/{id}/events?after=0 | NDJSON 已存事件与后续事件，按 seq 递增 |
| POST /api/runs/{id}/cancel | 显式取消自己的任务 |

事件 envelope：`{runId, seq, type, payload}`，type 为 delta/tool/stage/done/error/stopped/interrupted。连接保活不占用业务序号。断开订阅不改变 run 状态。

旧 `/api/chat` 与 `/api/debate` 仅保留经身份验证的兼容适配器，也走任务管理与限额，不形成另一条计费通道。先完成新页面迁移再停止旧客户端依赖，不更换 GLM 模型。

## 9. 验收重点

两个不同浏览器游客 + 主人同时登录：所有私有列表、猜 ID、流重连、停止与导出都不能串数据。站内切页不中断，刷新主人页恢复记录，游客刷新回入口。后台退出清理与超时按假时钟测试。网络断开重连不重复调用模型；进程重启只标记中断；删除后晚到 delta 不复活。主人的旧数据必须确认后才导入。

## 10. 已保存的附加修复需求

用户随后要求一起纳入三个局部问题，详细排查证据和验收写入配套实施计划的阶段 A1/A2：

- AI 科技订阅每卡单独刷新；区分缓存待更新与抓取失败，不把“新闻日期较早”称为过期。失败保留真实缓存，成功清除旧错误，按钮不触发全站重载；账号上线后主动抓取限主人。
- 每日复盘桌面同行的涨跌停卡片与成交额 Top5 卡片等高；移动端保持自然高度。
- 涨跌停详情使用不透明主题卡片：浅色为白色、暗色仍适配；不让黑色遮罩透过主体，不改数据和计算。
