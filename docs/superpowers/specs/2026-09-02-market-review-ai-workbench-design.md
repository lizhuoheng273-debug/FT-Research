# 每日市场复盘与统一金融 AI 工作台设计

**日期：** 2026-09-02  
**目标分支：** `codex/ft-research-v1-v2`

## 目标

把每日复盘从多个独立数据请求和页面内 AI 卡片，收敛为一个有明确新鲜度语义的每日市场快照；同时把复盘、金融资讯、指数、个股和分类 AI 入口收敛到一个可恢复上下文的 `/finance/ai` 工作台。指数图表必须展示真实指数价格，生产路径只能使用真实上游或真实缓存。

## 范围与非目标

本次范围包括：

- 修正股票/指数图表数据模型、指数分时/五日图以及真实数据失败策略。
- 新增 `GET /api/market/review` 统一快照接口，并保留旧市场接口兼容。
- 新增每日快照缓存、交易日判断、北京时间 15:30 盘后 AI 简述、补生成和幂等。
- 重排每日复盘页面，新增短线情绪和成交额 Top20 两个可访问弹层。
- 把全球指数行情条移到金融资讯页，不再由每日复盘请求全球行情。
- 新增统一 `/finance/ai` 全屏工作台和来源/资源标识恢复规则，兼容旧个股 AI 路由。

本次不包括：

- 改造上游数据供应商本身或新增付费数据源。
- 把 AI 生成的文字当作行情、宽度或成交额的事实来源。
- 在生产 API 中启用 fixture、合成行情或指数成交量冒充成交额。
- 修改 AI 资讯板块现有小抽屉交互。
- 修改外层“咨询平台”仓库。

## 设计原则

1. 客观行情先于解释：页面和 AI 都从快照或已有客观接口读取数据，AI 只解释传入上下文。
2. 真实数据优先：上游成功返回真实数据；短暂失败可返回最近一次真实缓存并标记 `stale`；没有真实数据就返回缺失/错误状态，绝不返回 fixture。
3. 事实与状态分离：`stale` 描述数据是否过期，`partial` 描述快照是否缺少可选或必要组件，`final` 描述是否已形成交易日收盘快照。
4. 资源小而稳定：URL 只放 `source`、`code`、`panel`、`eventId`、`date` 等标识，不放大段行情或新闻上下文。
5. 可验证交付：每个独立阶段先添加一个能复现目标行为的失败测试，再写最小实现、运行相关测试并提交。

## 后端架构

### 1. 图表模型

`backend/market_chart.py` 的点模型保持 OHLCV 结构，但把 `average` 类型改为 `float | None`。解析层只在上游明确提供有效均价时保留该值；股票的分时数据继续计算每日累计 VWAP，指数不计算 VWAP 且每个点的 `average` 为 `None`。股票与指数均保留真实 `quote` 中的最高、最低、最新、昨收、来源和抓取时间。

图表接口仍为 `/api/market/chart`。指数支持 `000001`、`399001`、`399006`、`000300`，`intraday` 和 `five_day` 的线图只使用 `close`，基准线使用真实的 `prevClose`；`five_day` 按最近五个真实交易日筛选，不用工作日造点。上游失败时沿用现有缓存回退语义，但缓存内容必须来自上游成功结果。

### 2. 统一市场复盘快照

新增一个聚合模块（实现位置遵循现有 backend 模块组织；预计为 `backend/market_review.py`），对各数据源做独立采集、规范化和缓存。FastAPI 在 `backend/app.py` 注册：

```text
GET /api/market/review
```

响应契约：

```json
{
  "tradingDate": "2026-09-02",
  "generatedAt": "2026-09-02T07:30:00Z",
  "final": false,
  "stale": false,
  "partial": true,
  "sources": [{"name": "...", "status": "fresh|stale|missing|error", "fetchedAt": "...", "detail": "..."}],
  "indices": [{"code": "000001", "name": "上证指数", "price": 3900.0, "change": 10.0, "changePct": 0.25, "source": "...", "updatedAt": "...", "stale": false}],
  "breadth": {"up": 1000, "down": 800, "upRatio": 55.56, "downRatio": 44.44, "limitUp": 30, "limitDown": 8},
  "liquidity": {"todayAmountYuan": 1000000000000, "previousAmountYuan": 900000000000, "changeAmountYuan": 100000000000, "changePct": 11.11, "direction": "expanded"},
  "shortTermEmotion": {},
  "turnoverTop": [],
  "sectors": [],
  "brief": {"text": "", "status": "pending|generated|unavailable|missing", "generatedAt": null, "promptVersion": "market-review-brief-v1"}
}
```

字段规则：

- `breadth` 只公开上涨、下跌、上涨比例、下跌比例、涨停、跌停；不公开平盘。比例分母为 `up + down`，有分母时两者合计 100%，无分母时返回缺失值而非 0。
- `liquidity` 只使用同一口径的上交所和深交所官方市场统计，限定沪深股票市场，不包含北交所、基金、债券、回购。今日和上一交易日走同一字段、同一聚合方式；不得从指数成交量推导成交额。
- `shortTermEmotion` 可包含最高连板、梯队、封板率、炸板率、晋级率及连板股票表，数据缺失时保留缺口状态。
- `turnoverTop` 默认由真实成交额排行产生，包含至少名称、代码、现价、涨跌幅和成交额；无数据时为空并通过来源状态说明。
- `sectors` 和资金趋势沿用现有板块能力；每项附带新鲜度/缺失语义。
- `partial=true` 表示一个或多个组件缺失；必要组件至少为三个主要指数、上涨/下跌家数和沪深成交额。必要组件不足时仍返回结构化快照，但 `brief.status` 不得是 `generated`。
- `stale=true` 表示至少一个返回的数据组件来自过期真实缓存；单个组件的 `stale` 必须传递到 `sources` 或组件字段。
- 盘中快照缓存 1 分钟，盘后快照缓存到下一个交易日；缓存文件放在 `backend/.cache/market-review/`，不进入 Git。

旧的指数、宽度、成交额、短线情绪和排行接口继续保留；页面、自动简述和金融 AI 上下文改为优先使用统一快照，兼容调用只用于旧页面或现有工具。

### 3. 盘后简述与调度

预计新增 `backend/market_review_brief.py` 与对应调度职责。服务输入为已生成快照、当前北京时间和交易日历判断结果，输出纯文本最多 200 个中文字符，并用 GLM 配置层现有的 `backend/.env` 配置调用聊天服务。Prompt 固定要求覆盖：

- 指数表现与分化；
- 沪深成交额及相对上一交易日的放/缩量金额和百分比；
- 上涨/下跌宽度；
- 涨跌停、题材投机与主要板块；
- 一句风险或数据缺口。

不得预测点位或给出买卖建议。短线情绪或板块缺失时可以生成，但文字必须明确指出缺口。少于三个主要指数、缺少上涨/下跌家数或缺少沪深成交额时不生成。

调度以北京时间判断每个交易日 15:30：后端运行中只触发一次；15:30 后首次启动时检查当天收盘快照并补生成；非交易日不生成。缓存文件为 `backend/.cache/market-review/YYYY-MM-DD.json`，同时保存快照哈希、Prompt 版本、生成状态、文本和时间。相同交易日 + 相同快照哈希 + 相同 Prompt 版本的成功结果幂等，不重复调用；失败不覆盖成功缓存，页面显示明确不可用/缺口状态。

### 4. AI 工作台后端边界

不新增另一套聊天协议。工作台继续调用 `/api/chat` 的 NDJSON 流，前端从 `source` 与资源标识重新加载页面数据并拼接受控摘要到现有 `context`。后端 `ChatReq` 和 `analysis_scope` 兼容现有约定；快照摘要可通过现有 `query_market` 工具或页面上下文供模型使用。

## 前端架构

### 1. 复盘页面

`frontend/src/pages/DailyReview.tsx` 只请求 `/api/market/review`（旧链接兼容由 API 层保留），页面自上而下为：标题及右上角问 AI、AI 收盘简述、四大指数、红绿宽度带与沪深成交额、左侧涨停/跌停摘要和右侧成交额 Top20 摘要、板块资金趋势、资金轮动。

删除首屏的关注股票、旧 AI 当日复盘、原市场情绪大卡、平盘数据、完整短线情绪表和完整 Top20 表。宽度带左侧红色显示上涨家数，右侧绿色显示下跌家数；下方显示今日成交额、较上一交易日金额差和百分比。缺失/过期状态与来源更新时间可见。

### 2. 两个大弹层

新增复盘页内可复用的访问性弹层组件或局部组件：

- 涨停/跌停摘要点击后打开完整短线情绪：最高连板、连板家数与梯队、封板率、炸板率、晋级率、连板股票表。
- 成交额摘要默认显示前 10 只，桌面两列各 5 只，只显示名称、现价、涨跌；点击榜单区域打开完整前 20 大弹层，点击具体股票跳转个股详情。

两个弹层均为桌面居中宽弹层、移动端全屏，支持遮罩点击、关闭按钮、Esc 和键盘焦点到达；打开时管理焦点，关闭后恢复触发按钮焦点。组件测试覆盖 10/20 数量、键盘关闭和股票跳转。

### 3. 全球行情位置

从 `DailyReview` 移除全球行情请求。把现有 `gstock.global_indices()` 对应的行情条移动到金融资讯页标题下、紧要快讯之前，保留中国市场红涨绿跌规则之外的全球行情展示信息：名称、地区、价格、涨跌幅、更新时间和缓存状态。全球行情失败只显示状态，不阻断资讯榜；现有“全球观察”海外事件区保留。

### 4. 统一 AI 工作台

新增 `frontend/src/pages/FinanceAiWorkspace.tsx`（命名可按现有代码风格调整）并在 `frontend/src/router.tsx` 注册：

```text
/finance/ai?source=review|news|watchlist|index|stock|stock-panel|news-story&code=...&panel=...&eventId=...&date=...
```

工作台复用 `useAiChatSession`、`AiConversation`、现有 Markdown 渲染、工具记录、保存回答、清空会话和停止生成。根据来源和标识重新请求数据，不把上下文正文塞入 URL；刷新后 URL 足以恢复页面数据。

会话 key 规则：

| 来源 | 会话隔离 key |
| --- | --- |
| 每日复盘 | `review:<tradingDate>` |
| 资讯首页 | `news` |
| 新闻事件 | `news-story:<eventId>` |
| 自选股 | `watchlist` |
| 指数 | `index:<code>` |
| 个股 | `stock:<code>` |
| 个股分类 | `stock-panel:<code>:<panel>` |

`/finance/stocks/:code/ai` 保留为兼容路径，并转发到同一工作台外壳；返回操作恢复原页面 pathname 和查询参数。资讯 AI 小抽屉不改。

## 错误与降级

- 任何真实上游异常都转成来源状态；有最近真实缓存就返回缓存并标记 `stale`，没有就返回缺失，不抛出会导致整页白屏的 fixture。
- 必要组件缺失时快照 HTTP 仍可成功返回结构化 `partial` 响应，让页面可展示其它组件；简述明确为 unavailable/missing。
- GLM 超时、HTTP 错误、格式错误或超过限制时保留上次成功简述；没有成功简述时显示失败原因的用户可读状态，不泄露 API Key。
- AI 工作台保留现有中止语义：中止或无内容错误不把半截回答持久化为完整会话，切换上下文时 abort 前一请求。

## 测试与验收

后端新增/修改测试覆盖：

- 四个指定指数的分时/五日 `average is None`、真实价格不被均价压扁、最近五个交易日筛选。
- 快照字段契约、宽度比例合计 100% 且无平盘、官方成交额同口径、必要组件缺失、真实缓存 stale、无缓存 missing、旧接口兼容。
- 盘中 1 分钟/盘后跨交易日缓存、15:30 调度、启动补生成、非交易日、哈希+Prompt 版本幂等、GLM 错误保护和 200 字限制。

前端新增/修改测试覆盖：

- 复盘首屏模块顺序和删除项、宽度/成交额展示、弹层桌面/移动端类名和可访问关闭、Top20 摘要 10 条与弹层 20 条。
- 全球行情只在金融资讯标题区，失败不阻断资讯榜。
- 所有金融 AI 入口指向统一工作台，来源标识、刷新恢复、会话 key 隔离、返回查询参数、流式与中止复用。

最终验收命令：后端完整离线测试、前端完整测试、`tsc -b`、生产构建；启动本地后端和前端后用浏览器检查四个指数、复盘布局、两个弹层、资讯全球行情和各 AI 入口。完成前不推送。

## 阶段与提交边界

1. 图表均价语义和指数线：独立测试与 commit。

3. 复盘页面、弹层和资讯全球行情：独立前端测试与 commit。
4. 统一 AI 工作台及入口迁移：独立前端测试与 commit。
5. 盘后简述、调度、幂等和最终集成：独立测试与 commit。
6. 全量验证和浏览器验收：只在证据齐全后报告，不推送远端。
