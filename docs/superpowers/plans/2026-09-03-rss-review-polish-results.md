# RSS 刷新与每日复盘样式执行结果

执行范围为 `2026-09-02-owner-guest-ai-sessions.md` 的 A1、A2。主人/游客登录、服务端对话历史及后台生成（Tasks 1–8）仍是保存的后续方案，本次未实施。

## 已实现

- 每个 RSS 卡片可独立刷新，保留现有文章；分别展示待更新、更新失败使用缓存、暂不可用，以及成功但没有新内容的提示。
- 内置信源只使用服务器登记的地址；自定义订阅核对规范化地址与 ID，保留内网和重定向安全检查。
- 同源 HTTP 刷新有 30 秒冷却，返回 429 和 Retry-After；URL 锁覆盖抓取及缓存写入，抓取并发最多 4 个，自动更新按各信源的到期时间调度。
- 使用 8 秒连接、最多 12 秒单次读取及 20 秒下载预算。每次重定向按剩余预算连接，不读取无用的重定向响应体；不能设置读取超时的未知响应包装器拒绝抓取，不启动遗留读取线程。
- 已补真实 urllib / 本地 socket 测试，覆盖正 Content-Length、负 Content-Length 及 chunked EOF，防止完整下载被误判为失败或过早截断。
- 手机 RSS 卡片操作区独立成行，避免正文被按钮挤窄。
- 每日复盘涨跌停与成交额 Top5 桌面等高，手机保留自然高度；长名称只撑开表格内部的可滚动区域。
- 短线情绪与 Top20 共用弹窗采用不透明主题卡片底色：浅色为白色，暗色沿用现有深色；未修改行情、均价、K 线、AI 提示词或榜单数据。

## 保留限制

- Python/系统的 `socket.getaddrinfo` 无法被当前线程强制中断。DNS 已在受限并发区执行并在调用前后检查预算，但不能承诺操作系统 DNS 卡住时全程必在 20 秒返回。
- 沿用现有 API 访问策略，没有新增主人/游客认证。部署多用户公开服务前，需完成后续认证与主动抓取权限控制，不应把本次刷新端点视为已经具备多用户隔离。
- 原有侧栏在手机宽度下展开较宽；本轮只修复内容卡片，手机验收使用收起侧栏，没有进行全站导航重构。
- 本地提交与验证不代表已合并、推送或部署；集成操作应按用户后续选择执行。
